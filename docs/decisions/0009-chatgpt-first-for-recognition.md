# 0009 辨識預設由 ChatGPT 優先，Claude 為可選備援

- 狀態：已採用

## 背景

本程式可同時設定兩個 AI 服務：ChatGPT 登入與 Claude API key。每次呼叫用清單中第一個啟用且可用的服務，所以「預設順序」決定了大多數辨識由誰處理。辨識要估克數，而克數是熱量的主要誤差來源（見 [0001](0001-kcal-computed-by-program.md)）。

這個決定是**根據研究做的**：

- Nutrition5k 多食物餐點的單項克數誤差（PMAE），GPT-5.5 為 38.7%，Claude Opus 4.8 與 Fable 5 約為 51–53%（[arXiv:2607.16514, 2026](https://arxiv.org/abs/2607.16514)）。
- 另一項研究中各模型都低估克數 12–37%，Haiku 5.5 約 −37%（[arXiv:2610.26538, 2026](https://arxiv.org/abs/2610.26538)）。Claude 在本程式的預設模型正是 Haiku 5.5（最便宜）。

## 考慮過的選項

**A. Claude 優先**
- 優點：API 用量可控、按 token 計費透明。
- 缺點：上述研究中 Claude 系列的克數誤差較大；預設的 Haiku 5.5 低估最多。

**B. ChatGPT 優先，Claude 為可選備援（採用）**
- 優點：依上述研究，克數誤差較小；使用 ChatGPT 方案額度，不需另外付 API 費用。
- 缺點：研究測的不是本程式實際使用的模型與設定。

**C. 依步驟分流（例如辨識用 ChatGPT、搜尋用 Claude）**
- 優點：每一步可用最適合的服務。
- 缺點：設定與程式都變複雜，也沒有逐步比較的數據。未實作。

## 決定

採用 B。預設清單順序為 ChatGPT 在前、Claude 在後；這只是**預設**，不是保證。

## 做法

1. **預設值**：`server/app.js` 的 `providerConfig()` 預設為 ChatGPT（啟用）、Claude（未啟用，模型為 `DEFAULT_CLAUDE_MODEL`，即 `server/claude.js` 的 Haiku 5.5，沒有 API key）。
2. **使用者可調整**：在「設定 → AI 服務」可以改順序、啟用或停用；保存的順序優先於預設順序。
3. **可用才列入**：`providerChain()` 依序列出啟用且可用的服務（ChatGPT 要已登入且有方案授權，Claude 要有 API key）；ChatGPT 所選模型不可用時略過。
4. **只在特定錯誤時備援**：`server/food-routes.js` 的 `fallbackWorthy()` 判斷是否換下一個服務：HTTP 400、401、403、429、5xx、逾時（已重試 1 次）、網路錯誤，以及額度、限流等訊息。回傳內容格式錯誤、Claude 拒絕、使用者中止則不換。
5. **標註實際處理的服務**：每個 AI 處理的項目在備註註明服務與模型，結果也帶 `servedBy`，可看出是否由備援處理。

## 取捨

- 上述研究沒有測試本程式實際使用的模型與設定（例如 GPT-5.6-Sol），也不是用本程式的提示詞，結果只能當方向參考。
- 數字為原論文在其資料集上的結果，實際效果依使用情境而異。
- 備援會在使用者沒注意時改由另一個服務處理（見 [0007](0007-structured-output-search-step.md) 的「注意」），只能靠備註與 `servedBy` 查看。

## 何時重新評估

- 任一方推出新的模型版本，或出現新的克數誤差比較研究。
- 用自己記錄的餐點（有修正過克數的項目）比較兩個服務的克數誤差。
